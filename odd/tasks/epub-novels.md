## Decisions

D1. **No EPUB dependency.** `java.util.zip` plus small XHTML/OPF/nav/NCX templates covers this text-only, single-chapter export. A general EPUB library would add APIs and dependencies without needed capabilities; the standard-library option is sufficient. No claim is made about the current maintenance of alternative libraries.

D2. **EPUB 3 package with a legacy NCX fallback.** `nav.xhtml` (`properties="nav"`) is the EPUB 3 navigation; `toc.ncx` + `spine toc="ncx"` provides older readers with navigation. A single `novela.xhtml` chapter preserves whitespace with `white-space: pre-wrap`. Reader compatibility still requires device verification.

D3. **Faithful text.** The delivered text is XML-escaped, not interpreted: if Pixiv returns markup it stays visible literally, exactly like the TXT output. XML-illegal control characters and unpaired surrogates are dropped so the package stays valid; every other code point (accented Latin, Japanese, emoji) is preserved as UTF-8.

D4. **`dc:language` = `und`.** Pixiv does not report the novel language through the existing client; guessing `es`/`ja` would be wrong data. `und` is a valid BCP 47 tag.

D5. **Stable publication identifier.** The `dc:identifier` is a name-based UUID over title + author + text, so re-downloading the same work yields the same identifier. `dcterms:modified` uses the writing time (injected in tests); ZIP timestamps mean the archive itself is not byte-deterministic.

D6. **Gallery.** `application/epub+zip` is stored as the entry MIME by `DownloadService`; the gallery tile uses the document icon, the card shows `EPUB`, and the detail/fullscreen view shows an explicit "cannot preview here" message with "Open with another app" only when an activity resolves.
